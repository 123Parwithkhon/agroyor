# AgroYor

Аренда сельхозтехники и ежедневные цены рынков Согдийской области (Худжанд, Истаравшан, Исфара).
Интерфейс на таджикском (по умолчанию), русском и английском. Словари — `lib/i18n.ts`;
`npm test` проверяет, что во всех языках есть каждый ключ и нет непереведённых строк.

Стек: Next.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS 4, PostgreSQL через postgres.js
(Neon в продакшене, PGlite локально), next-auth v5, zod, Recharts, Vercel Blob.

## Локальный запуск

Нужен Node.js 24 или новее.

```bash
npm install
cp .env.example .env          # затем задайте ADMIN_PHONE, ADMIN_PASSWORD, AUTH_SECRET
npm run db:migrate            # создаёт схему в .data/pglite
npm run db:seed -- --demo     # рынки, продукты, админ + демо-данные (только локально)
npm run dev                   # http://localhost:3000
```

`npm run dev` сам поднимает локальную базу. Отдельно запускать ничего не нужно.

Демо-данные (`--demo`, только локально): 9 пользователей, 14 объявлений всех видов техники,
11 броней (завершённые, подтверждённые, ожидающие), 7 отзывов и цены 3 рынков за 30 дней.
Пароль всех демо-пользователей — `demo1234`, телефоны `+992900000001` … `+992900000009`
(`+992900000003` — репортёр цен). Повторный запуск ничего не дублирует и обновляет цены до сегодняшнего дня.
Сами данные лежат в `scripts/lib/demo-data.mjs`.

## Как устроена база

- `DATABASE_URL=pglite://.data/pglite`: локальный PGlite (Postgres в WebAssembly, файлы в `.data/`).
  `npm run dev` и скрипты `db:*` запускают его как TCP-сервер на `127.0.0.1:PGLITE_PORT` (по умолчанию 5433),
  а приложение подключается к нему через postgres.js, как к обычному Postgres.
  Приложение держит к локальному PGlite **одно** соединение: при параллельных запросах из нескольких
  соединений мультиплексор PGlite путает ответы. Это проверено, страница объявления получала пустой результат.
- `DATABASE_URL=postgres://...`: Neon в продакшене (обычный пул соединений).
- Миграции лежат в `db/migrations/*.sql`, применяются по порядку имён (`npm run db:migrate`), а учёт ведётся в таблице `schema_migrations`.
  Уже применённую миграцию не редактируйте, для изменений создавайте новый файл.
- Пересечение подтверждённых броней запрещено exclusion constraint'ом (`btree_gist`).
- Локально postgres.js подключается с `fetch_types: false` (`lib/db.ts`, `scripts/lib/local-db.mjs`): на pglite-socket
  служебный запрос типов вешает транзакции и запросы с enum-колонками (подтверждение брони зависало). Не включайте.
- Чтобы начать с чистой локальной базы, остановите `npm run dev` и удалите папку `.data/`.

## Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | локальная БД + dev-сервер Next |
| `npm run build` / `npm start` | продакшен-сборка и запуск |
| `npm run start:local` | продакшен-сборка с локальной БД (проверка скорости, Lighthouse) |
| `npm run typecheck` | проверка типов |
| `npm run lint` | ESLint |
| `npm test` | тесты (`node:test`): телефоны, деньги, даты, язык, валидация форм, правила броней и цен; подтверждение брони — на своём PGlite в памяти (dev-сервер не нужен, база разработки не меняется) |
| `npm run db:migrate` | применить новые миграции |
| `npm run db:seed` | рынки, 8 продуктов, админ из `.env`; `-- --demo` добавляет демо-данные, только для pglite |

Проверить, что всё работает: `GET /api/health` отвечает `{"ok":true,"markets":3,"products":8}`.

## Стиль: Центральная Азия

Оформление в духе таджикского искусства. Палитра (токены в `app/globals.css`, классы Tailwind):

| Токен | Что это | Где используем |
|---|---|---|
| `lapis-*` | ляджувард (лазурит) | шапка, подвал, заголовки |
| `firuza-*` | фирӯза (бирюза куполов) | основные кнопки и ссылки на светлом фоне |
| `zar-*` | зар (золото) | акценты, активные элементы на тёмном фоне |
| `anor-*` | анор (гранат) | звёзды у заголовков, рамка фокуса |
| `sand-*` | тёплый кремовый | фон, рамки карточек |

Орнаменты — `components/ornaments.tsx` (звезда-гирих, медальон сюзане, заголовок `OrnateHeading`)
и CSS-классы `bg-girih`, `ornament-strip`. Всё сделано на SVG и CSS, без картинок, поэтому не замедляет 3G.
Тёмные блоки помечаем классом `on-dark`: рамка фокуса на них золотая, а не гранатовая.

## Адаптивность (правила для всех страниц)

- Вёрстка mobile-first: базовые классы описывают телефон, `sm:` (≥640px) и `lg:` (≥1024px) — шире.
  Проверяем на ширине 320, 360, 768 и 1280px: горизонтальной прокрутки быть не должно.
- На телефоне навигация — нижняя панель вкладок (`components/BottomNav.tsx`), с 640px — меню в шапке.
  У `body` на телефоне есть нижний отступ под панель, его не убирать.
- Кнопки и ссылки — не меньше 44×44px (`min-h-11`), основные действия — `min-h-14`, во всю ширину на телефоне.
- Поля ввода — шрифт не меньше 16px (задано в `globals.css`), иначе iPhone увеличивает страницу.
- Широкие таблицы (цены по рынкам) — в обёртке `overflow-x-auto`, первая колонка закреплена.
- Сетки карточек: 1 колонка на телефоне → `sm:grid-cols-2` → `lg:grid-cols-3`.

## Структура

```
app/            страницы (App Router), Server Actions в app/actions
components/     простые компоненты без UI-китов
lib/            db, i18n (словари tj/ru), format, phone, password, districts
db/migrations/  SQL-миграции
scripts/        migrate, seed, dev (локальный PGlite)
public/fonts/   Noto Sans (OFL), чтобы сборка не зависела от Google Fonts
tests/          тесты (импорты @/ понимает tests/alias-hooks.mjs)
```

Шрифт `noto-sans-tajik.woff2` — урезанный cyrillic-ext Noto Sans (только Ғғ Ққ Ҳҳ Ҷҷ Ӣӣ Ӯӯ, 3,5 КБ).
Шрифты кешируются браузером на год, поэтому при замене файла меняйте его имя.
